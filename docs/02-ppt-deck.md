# Agent Bento — PPT 演示大纲与讲稿（NotebookLM 源文档）

文档类型：演示文稿脚本  
建议页数：12 页（可压缩为 8 页快版 / 扩展为 16 页深版）  
时长：约 6–8 分钟讲解 + 2 分钟现场操作  
演示环境：`npm run dev` → `/` 与 `/dashboard`  
口径：Simulated 不得说成已上线

使用方式：把本文上传 NotebookLM 后，可要求「按页生成幻灯片」「生成演讲者备注」「改成 90 秒版」。

---

## 演示目标（开场前默念）

1. 听众理解：**不是摄像头监控，是异常沉默 → 人工关怀 → 必要时升级**。  
2. 听众相信：**隐私与尊严优先**。  
3. 听众分清：**现在能演示什么 / 还缺什么**。  
4. 现场能指着 UI 讲完一条完整故事。

---

## 幻灯片逐页

### 第 1 页 — 封面

**标题：** Agent Bento  
**副标题：** 发现异常沉默，派人温柔确认，必要时才通知家人  
**角标：** Privacy-first home safety · Prototype  

**讲稿：**  
「这是 Agent Bento。我们不做盯梢，我们做一张会在沉默太久时敲门的安全网。」

**屏幕建议：** 落地页全屏，或产品 logo + 日本住宅静帧。

---

### 第 2 页 — 问题

**标题：** 独居老人最可怕的，不是跌倒本身，而是「没人发现」  

**要点：**
- 家人远距离，日常无法实时陪护  
- 摄像头不愿装、呼叫钮够不到  
- 「立刻报警」误报多，信任崩掉  

**讲稿：**  
「当老人长时间不动，家人会问：是睡着了，还是需要帮助？我们要解决的是这个不确定性，而不是把家变成监控室。」

**对应演示故事副题（来自 demo meta）：**  
「当独居老人不再移动，是睡着了还是需要帮助？」

---

### 第 3 页 — 洞察

**标题：** 异常沉默值得警惕，但第一步不该是恐慌  

**要点：**
- 先低压力人工确认（便当上门敲门）  
- 有回应 → 关闭事件  
- 无回应 → 再通知信任联系人  

**讲稿：**  
「产品承诺就一句话：Notice unusual silence, send human care, escalate only when needed。」

---

### 第 4 页 — 方案总览

**标题：** 三层：感知 · 策略 · 关怀  

**要点：**
1. **感知**：Wi‑Fi CSI 环境反射 → 移动 / 静止模式（无摄像头、无麦克风）  
2. **策略**：确定性阈值与状态机（模型只能解释，不能绕过）  
3. **关怀**：便当 check-in → 家人通知 → 审计时间线  

**讲稿：**  
「AI 可以帮忙把事件说成人话，但『要不要上门、要不要通知家人』必须由可测试的规则决定。」

**图示建议：**

```text
Wi‑Fi CSI → 事件归一化 → 风险策略 →（Qwen 解释）→ 便当上门 → 家人升级 → 审计日志
```

---

### 第 5 页 — 隐私

**标题：** 为什么不是摄像头方案  

**要点：**
- 不拍脸、不录说话  
- 只关心「有没有像平时那样在动」  
- 居民同意、联系人可配、安静时段（规划中）  
- 不是医疗诊断设备  

**讲稿：**  
「我们卖的是尊严感：安全网在，但家里不必 24 小时被看见。」

---

### 第 6 页 — 现场演示 A：落地页故事

**标题：** Demo A — 3D 小屋讲清三种状态  

**操作步骤：**
1. 打开 `/`  
2. 展示 **正常活动**  
3. 切到 **异常沉默**  
4. 切到 **人工上门 / 便当确认**  
5. 可拖动旋转小屋（强调是实时 3D，不是视频）  

**讲稿：**  
「左侧是故事，右侧是空间。观众一眼看到：沉默被发现，然后是人来敲门，而不是弹窗吓人。」

**页脚诚实句：** 故事状态为演示编排（Simulated）。

---

### 第 7 页 — 现场演示 B：家人仪表盘

**标题：** Demo B — 用你家的户型图看「爷爷还好吗？」  

**操作步骤：**
1. 打开 `/dashboard`  
2. 上传户型照片 → 自动房间框（Qwen Cloud，需 Key）→ 确认 → 钉 Wi‑Fi  
3. 强调：**地图就是那张上传图**，房间框不可见，只用于位置映射  
4. 指出亮绿 Grandpa 标记与 Wi‑Fi 钉  
5. 播放故事回放：日常 → 沙发静止 → 异常 → 骑手 → 敲门 → 只是睡着 → 恢复  

**演示故事场景表（可做成小表）：**

| 场景 | 内容 |
| --- | --- |
| S1 日常快切 | 起床→厨房→客厅 |
| S2 沙发静止 | 逐渐不动 |
| S3 异常检测 | 启动决策链 |
| S4 骑手在路上 | 接单赶往 |
| S5 上门检查 | 敲门，老人醒来 |
| S6 确认安全 | 只是睡着了 |
| S7 总结恢复 | 继续守护 |

**页脚诚实句：** 回放数据来自本地 `demo_frames.json`（Simulated）。

---

### 第 8 页 — CSI 可视化

**标题：** 把看不见的 Wi‑Fi，翻译成看得见的场  

**要点：**
- 线框人体：存在 / 姿态示意  
- 青色球面：相位 / 波前感  
- 绿色格点：占用 / 能量场  
- 粒子：运动能量  
- HUD：合成读数，标 Simulated  

**讲稿：**  
「这页是为了让非技术听众理解：没有摄像头，也能谈『有人在、有没有动』。数字不是医院监护仪。」

**操作：** `/dashboard` 滚动到 CSI · HUMAN FIELD，可拖动轨道。

---

### 第 9 页 — 真假边界（关键页，评委爱问）

**标题：** 今天真的有什么 / 还没有什么  

**Implemented（真有）：**
- 落地页与仪表盘 UI  
- 户型上传与（可选）视觉房间检测  
- 监测地图与 Grandpa 标记  
- 合成 CSI 可视化与单测 / 构建检查  

**Simulated（像真的）：**
- 活动故事与便当 / 家人结局  
- CSI 数值与「似生命体征」HUD  

**Planned（规划）：**
- ESP32-S3 真机 CSI  
- 持久化事件状态机  
- 真实下单与通知  
- 同意、基线校准、运营台  

**讲稿：**  
「我们故意把假的标清楚。这是产品工程诚实，也是安全系统的底线。」

---

### 第 10 页 — 技术与架构（给技术听众）

**标题：** 当前栈与目标边界  

**当前：** Next.js 16 · React 19 · R3F · Vercel 服务端 · GMI Cloud 活动推理 · Qwen Cloud 户型视觉  
**目标适配器：** SensorAdapter · RiskPolicy · ReasoningAdapter · CheckInProvider · NotificationProvider · IncidentRepository  

**原则：**
- 本地模拟器与真机走同一接口  
- 幂等下单 / 通知  
- 策略确定性 + 模型结构化输出与超时降级  

---

### 第 11 页 — 路线图

**标题：** 下一步  

1. 共享事件机 + 转换测试  
2. 本地事件模拟器对接同一 API  
3. ESP32 CSI 接入与家庭基线  
4. 配送 / 通知适配器  
5. 同意与家人确认控件  
6. 隐私 / 无障碍 / 失效模式 / 实地测试 → 试点  

---

### 第 12 页 — 收尾

**标题：** Agent Bento  
**金句：** 沉默值得警惕；关怀先于警报；升级只在必要时。  
**行动号召：** 打开原型 `/` → `/dashboard`；需要资料见 `docs/`  

**Q&A 预告：** 「是医疗器械吗？」「误报怎么办？」「数据存哪里？」→ 见 FAQ 文档。

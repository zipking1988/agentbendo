## 一句话是什么

**Agent Bento** 是一套面向独居或长时间独自生活的老年人的、**隐私优先的居家安全关怀系统**。它用 **环境 Wi‑Fi 传感**（不看摄像头、不录麦克风）察觉「长时间异常沉默」，先用 **便当上门** 做低压力人工确认，只有确认不到人时才通知家人或信任联系人。

产品承诺（固定口径）：

> Notice unusual silence, send human care, and escalate only when needed.  
> 发现异常沉默 → 派人温柔确认 → 必要时才升级通知。

---

## 要解决什么问题

独居老人跌倒、昏倒或突然长时间不动时，家人往往很晚才发现。传统方案常见问题：

1. **摄像头 / 麦克风**：侵入感强，老人不愿装。
2. **紧急呼叫钮**：摔倒后可能够不到。
3. **立刻报警式 App**：误报多，家人疲劳，老人反感。

Agent Bento 的切入点：**异常沉默值得警惕，但先用「人」确认，而不是先制造恐慌**。便当骑手敲门既是关怀，也是一次可审计的人工检查。

## 为谁服务

| 角色 | 需要什么 |
| --- | --- |
| 独居老人（Resident） | 尊严、隐私、少打扰；同意与可控 |
| 家人 / 信任联系人（Family） | 「爷爷还好吗？」一眼能懂；只在需要时被叫 |
| 骑手 / 上门确认方（Courier） | 清楚任务：送便当 + 敲门确认 |
| 运营 / 护理协调（Operator，规划中） | 可审计事件时间线与策略规则 |

## 理想工作流程（目标产品）

1. 家中 **Wi‑Fi CSI（Channel State Information）** 设备感知人体移动引起的无线电反射变化；**不采集图像与语音**。
2. **确定性风险策略**（不是模型拍脑袋）对比「平时习惯」与「当前异常静止」。
3. 异常沉默持续超过策略阈值 → 进入观察 / 事件，而不是立刻当急救。
4. 系统请求 **便当配送上门** 作为低压力 check-in。
5. 老人回应 → 事件关闭，记录原因。
6. 无人回应 → **按同意名单通知家人**；仍无响应则按策略进一步升级。
7. 每一步状态迁移写入 **可审计时间线**（谁、何时、何规则、何动作）。

目标状态机（生产设计，代码尚未全部落地）：

```text
NORMAL → WATCH → CHECK_IN_REQUESTED → CHECK_IN_EN_ROUTE
  → RESIDENT_RESPONDED 或 FAMILY_ALERTED → HANDOFF_COMPLETE / ESCALATED → RESOLVED
```

## 仓库里现在有什么（原型）

本仓库是 **可交互的产品原型 + 未来服务层脚手架**，不是已量产的完整硬件平台。

### 落地页 `/`

- 日本住宅风格的 **3D 剖切小屋**（Three.js / React Three Fiber）。
- 三种故事状态：正常活动、异常沉默、人工上门确认。
- 「Inspired by My Grandma」叙事与隐私说明。
- CTA 进入家人仪表盘 `/dashboard`。

### 家人仪表盘 `/dashboard`

1. **上传户型图**（照片或草图）。
2. **Qwen Cloud 视觉模型**自动框出客厅 / 厨房 / 卧室 / 浴室区域（需 API Key）。
3. 用户确认房间 → **钉 Wi‑Fi 位置** → 解锁监测。
4. **监测地图 = 用户上传的那张图**（不画彩色房间框、不显示房间名贴纸、不做 AI 重绘、不做仪表盘 3D 娃娃屋）。
5. 房间框只作为 **看不见的数据**，用来把演示故事里的 Grandpa 位置映射到图上。
6. 高对比 **Grandpa 标记**（亮绿 + 深描边）+ Wi‑Fi 钉。
7. **平静视图**（「爷爷还好吗？」）+ 本地 `demo_frames.json` **故事回放**。
8. **CSI 信号场可视化**（Matrix 风格：线框骨架、青色波球面、热力格点、粒子、HUD）——数据来自合成 RF 规则，**不是真机 CSI，不是临床生命体征**。

本地运行（Node.js ≥ 22.13）：

```bash
npm install
npm run dev   # http://localhost:3000/
```

## 技术栈（当前）

- 应用：Next.js 16、React 19、TypeScript  
- 构建与服务端：原生 Next.js，部署于 Vercel  
- 3D：Three.js、React Three Fiber、Drei、Postprocessing  
- 活动推理：GMI Cloud Inference Engine（只接收本地提取的隐私安全特征）  
- 户型视觉：Qwen Cloud（`qwen-vl-max`；环境变量 `QWEN_API_KEY` 仅服务端）  
- 数据脚手架：Drizzle ORM（未来持久化）  
- 硬件规划：ESP32-S3 + Wi‑Fi CSI  
- 推理规划：Qwen 结构化输出（解释与建议，**不能绕过确定性策略**）

## 隐私与安全原则

1. 无摄像头、无音频录音作为传感手段。  
2. 居民明确同意；联系人与安静时段可配置（规划中）。  
3. 只收集移动分析所需的最少信号特征；原始 CSI 宜短留、可选。  
4. 先低压力可逆动作，再升级。  
5. 让家人理解「为什么触发」。  
6. 模型建议不能绕过策略、不能独自启动急救。  
7. 支持取消、确认、事后审查。  
8. 不做医疗诊断宣称。

## 与「CSI 可视化」的关系

仪表盘里的 CSI 场是 **把「看不见的 Wi‑Fi 信道状态」翻译成可演示画面**：

- 振幅感 → 颜色 / 亮度  
- 相位感 → 青色扩散球面  
- 运动能量 → 粒子密度  
- 微动 / 「似生命体征」→ 光晕与 HUD 数字（一律标 **Simulated**）

它帮助观众理解 **为什么不需要摄像头也能谈「有人在动」**；它不是临床试验界面。

## A. 产品是什么

### Q1. Agent Bento 是什么？

Agent Bento 是隐私优先的居家安全关怀原型：用环境 Wi‑Fi 运动信号察觉独居老人「异常沉默」，先安排便当上门做人工确认，只有无人回应时才通知信任联系人。

### Q2. 一句话产品承诺是什么？

英文：Notice unusual silence, send human care, and escalate only when needed.  
中文：发现异常沉默，派人温柔确认，必要时才升级通知。

### Q3. 它是医疗设备吗？

不是。它是辅助安全 / 关怀系统，描述的是活动与沉默模式以及关怀动作，不做诊断、不开处方、不替代急救体系。

### Q4. 为什么叫 Bento / 便当？

便当配送是一种「低压力、有理由上门」的人工 check-in：敲门确认是否有人回应，而不是一上来就制造紧急警报。演示故事里会出现便利店骑手送餐上门的情节（Simulated）。

### Q5. Agent Bento 和「Bendo」是什么关系？

同一产品叙事。仓库与品牌以 **Agent Bento** 为准；本地演示数据 `demo_frames.json` 的标题使用「Bendo」字样，讲解时可说明为同一概念。

## B. 传感与隐私

### Q6. 用摄像头吗？

不用摄像头作为传感手段。也不以麦克风录音为传感手段。

### Q7. Wi‑Fi CSI 是什么？

CSI（Channel State Information）描述 Wi‑Fi 信道如何被环境改变。人体移动会改变反射与多径，从而在 CSI 特征上留下「有人在动 / 长时间不动」的线索。规划硬件是 ESP32-S3（Planned）；当前仪表盘 CSI 画面是合成可视化（Simulated）。

### Q8. 会不会偷听说话、认出是谁？

产品定位不采集对话音频、不做人脸识别。当前原型也没有真实 CSI 隐私攻击演示。任何未来真机部署都必须最小必要特征、同意与审计。

### Q9. 原始 CSI 要长期存吗？

工程原则：原始 CSI 宜短留、可选；优先存派生的活动特征。当前演示主要用本地故事帧与合成样本，并非生产级传感器库。

## C. 关怀流程

### Q10. 触发后会立刻叫救护车吗？

目标产品设计是分级：异常沉默 → 观察 → 便当上门确认 → 无人回应再通知家人 → 再按策略升级。演示里的阈值与结局是剧本化的（Simulated），不是已上线急救联动。

### Q11. 状态机有哪些状态？

生产设计包含：NORMAL、WATCH、CHECK_IN_REQUESTED、CHECK_IN_EN_ROUTE、RESIDENT_RESPONDED、FAMILY_ALERTED、HANDOFF_COMPLETE、ESCALATED、RESOLVED。完整持久化引擎仍属 Planned。

### Q12. AI（如 Qwen）能自己决定报警吗？

不能。确定性策略拥有阈值、升级、同意检查与最终派发权限。模型可做摘要、解释、排序建议；必须结构化校验、超时与确定性降级。

## D. 当前原型能演示什么

### Q13. 打开哪些网址？

本地开发服务器通常是 `http://localhost:3000/`（落地页）与 `http://localhost:3000/dashboard`（家人仪表盘）。

### Q14. 落地页演示什么？

日本住宅风格 3D 剖切屋、三种故事状态（正常 / 沉默 / 上门确认）、隐私文案、进入仪表盘的 CTA。3D 在 `/`；仪表盘不做娃娃屋 3D。

### Q15. 仪表盘设置流程是什么？

上传户型图 → Qwen Cloud 视觉检测房间框（需服务端 API Key）→ 用户确认 → 钉 Wi‑Fi 位置 → 解锁监测。设置存在浏览器 localStorage（`agent-bento.home-setup.v4`）。

### Q16. 监测地图上为什么看不到彩色房间？

有意设计：上传图即地图；房间区域是不可见数据，只用于把 Grandpa 映射进客厅/厨房等；不画彩色框、不贴房间名、不做 AI 重绘。

### Q17. CSI 面板上的心率 / 呼吸真实吗？

不真实。HUD 上的 BPM / RPM 等是合成微动读数，界面标 **Simulated**，不是临床生命体征。

### Q18. 演示故事有哪些场景？

S1 日常快切 → S2 沙发静止 → S3 异常检测 → S4 骑手在路上 → S5 上门检查 → S6 确认安全（睡着）→ S7 总结恢复。数据来自 `public/data/demo_frames.json`。

## E. Implemented / Simulated / Planned 速查

- Next.js 产品落地页与家人仪表盘 UI  
- 落地页 3D 小屋与故事控件  
- 户型上传、房间模型存储、Wi‑Fi 钉、Grandpa 监测标记

- 基于演示帧的 Wi‑Fi 活动、静止时长与变化趋势
- 构建与部分单测 / 渲染检查  

### Simulated（模拟）

- 故事回放中的活动、异常、便当、家人结果  
- 回放中的 Wi‑Fi 活动趋势
- 浏览器内户型与钉点（非真机标定）

- ESP32-S3 CSI 固件与事件桥  
- 持久化事件状态机与 Incident API

- 居民同意、安静时段、基线校准、运营工具

## F. 技术速答

### Q19. 主要技术？

Next.js 16、React 19、TypeScript、Vercel 服务端、Three.js / R3F、GMI Cloud 活动推理、Qwen Cloud 视觉、Node 测试。

### Q20. 如何本地运行？

需要 Node.js 22.13+。`npm install` 后 `npm run dev`。另有 `npm run build`、`npm test`、`npm run lint`。户型视觉需 `QWEN_API_KEY`（仅服务端，勿放进客户端或公开文档）。

### Q21. NotebookLM 不该上传什么？

不要上传 `.env`、`.dev.vars`、API Key、真实老人地址与联系人、整份超大 `demo_frames.json`（可用本 FAQ 中的场景表代替）。

## G. 评委刁钻问题（建议口径）

### Q22. 误报怎么办？

靠基线校准、安静时段、证据门槛、可取消与人工确认；先上门再升级。当前演示阈值是剧本，不是生产误报率数据。

### Q23. 和智能手环比呢？

可穿戴需要天天戴、充电；Wi‑Fi 环境传感目标是「家里空间里有没有异常沉默」。两者可互补，不是互相替代的唯一答案。

### Q24. 商业模式是什么？

本资料包聚焦产品与原型，不臆造未写明的定价。可讨论方向：家庭订阅 + 关怀派发成本 + B2B 护理机构，但标注为开放问题。

### Q25. 最大技术风险？

真机 CSI 在真实多径家居中的稳定性与标定；配送与通知的可靠性与幂等；把演示状态机误当成生产真相。

## H. 事实卡（Briefing 用短段）

**问题：** 独居老人异常不动时，家人往往发现太晚；摄像头方案接受度低。  

**方案：** 环境 Wi‑Fi 感知沉默 → 确定性策略 → 便当上门确认 → 必要时通知家人。  

**现状：** 可交互网页原型（落地页 + 仪表盘 + 合成 CSI）；硬件与真实派发仍在规划 / 模拟。  

**原则：** 隐私优先、策略确定性、模型不绕过安全边界、演示诚实标注。  

**金句：** 沉默值得警惕；关怀先于警报；升级只在必要时。

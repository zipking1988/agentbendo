# Agent Bento FAQ

## Q1. Agent Bento 是什么？

它是一个隐私优先的居家照护概念。当互动故事中的住宅出现异常安静时，产品先请求一次便当配送员上门确认，再根据结果更新家人。

## Q2. 为什么使用便当配送？

便当提供一个熟悉、自然且低压力的上门理由，同时把实际帮助与人的确认结合起来。

## Q3. 当前真的在监测住宅吗？

没有。公共产品是互动原型，活动信号、异常静止、配送、长者回应和通知均由本地脚本模拟。

## Q4. 当前使用云端模型或人工智能服务吗？

没有。当前仓库不调用云端模型服务，也不依赖相关密钥。

## Q5. 可以上传并自动分析自己的户型图吗？

不可以。当前产品使用仓库内置的日本住宅示例户型图。过去的自定义上传和自动分析能力已经移除。

## Q6. 家庭演示如何开始？

从首页选择 **Open family demo**，确认或调整示例图上的路由器位置，然后选择 **Start demo**。

## Q7. 为什么地图上仍有房间数据？

示例户型包含预先定义的四个故事区域，用于把模拟的长者位置放在客厅、厨房、卧室和浴室中。这些坐标只服务于演示。

## Q8. Technical demo details 是真实数据吗？

不是。它是根据当前故事帧绘制的模拟 Wi-Fi 活动轨迹，并明确标记为 Simulated。

## Q9. 是否使用摄像头或麦克风？

公共原型不使用摄像头或麦克风录音。真实产品仍需对传感硬件、同意、数据保留和安全控制进行验证。

## Q10. 这是医疗设备吗？

不是。Agent Bento 不提供诊断，也不能替代紧急服务或专业医疗建议。

## Q11. 什么已经实现？

落地页、示例户型设置、家庭仪表板、同步回放、照护旅程、模拟活动轨迹、浏览器本地保存和自动化检查。

## Q12. 什么仍是计划？

真实硬件、居民同意、校准、设备健康、持久化事件、真实配送、通知、审计和现场测试。

## Q13. 什么是 RuView 路由？

仓库保留一个独立的实验性 HTTP 桥接路由，用于未来硬件探索。它没有连接到公共家庭演示，也不应在演示中描述为已上线能力。

## Q14. 如何本地运行？

需要 Node.js 22.13 或更新版本。运行 `npm ci` 和 `npm run dev`，然后访问 `http://localhost:3000`。检查命令包括 `npm run lint`、`npm run build` 和 `npm test`。

## Q15. 演示时最重要的真相是什么？

明确说出：这是一个完整的产品体验原型，当前传感和服务动作均为模拟；它验证的是照护流程、信息层级和人的上门确认概念。
